# TeleFlow Phase 1: Electron scaffold, IPC bridge, and packaging spike

FileGram is gone from the branch (105 paths removed with `git rm -r`) and replaced by a minimal Electron 44 + electron-vite + React app that boots, loads TDLib 1.8.66 from `app.asar.unpacked`, and shows the API Keys step of Login. The main process resolves a data home outside the repo and the install folder, and routes every renderer call through one Electron-free `handleCall` with a page-key sender check. The packaged `TeleFlow.exe` is smoke-tested through its lowercased path, which proves the check against Chromium's drive-letter canonicalization. Items 1.1–1.3 landed as one commit; the Decision log records why. Requested checks pass: exact pins, no FileGram file in `git ls-files`, no mockup sample under `electron/`, `core/`, or `web/src/`, every gate command and result recorded in PROGRESS, and the main-workspace docs mirror identical to the worktree.

Watch for: nothing blocking. The `log()` secret mask and 5 MB rotation ship without a test (confirmed) and should get one before `auth.credentials` starts carrying the API hash in Phase 2. The build-time CSP lists `frame-ancestors`, which a `<meta>` policy ignores (confirmed). `.gitignore` still carries a dozen FileGram runtime entries (confirmed).

**Verdict**: APPROVED

## High-level view

The stack and electron-builder block match ARCHITECTURE > Tech stack and > Build exactly, with `tdl` and `prebuilt-tdlib` as the only runtime dependencies. FileGram survives only as stale ignore rules.

Runtime data goes to `TELEFLOW_HOME`, else `%LOCALAPPDATA%\TeleFlow` (packaged) or `TeleFlow-dev` (dev), with `userData` and `sessionData` pointed there before the single-instance lock. `resolvePaths` refuses a home equal to or inside `appDir`. An end user can trigger that refusal by installing into `%LOCALAPPDATA%\TeleFlow`, and its message only makes sense to a developer.

Bridge step 1 moved from the `ipcMain.handle` callback into `handleCall`, so the whole security path (sender check, own-property lookup, validation, envelope) runs under `node:test`. ARCHITECTURE's snippet still shows the old placement.

The packaging spike built `TeleFlow-Setup-1.0.0.exe` and `win-unpacked\TeleFlow.exe` with no native rebuild, and `test:app` covers every spike question from 1.3; the results are in ARCHITECTURE > Early-risk findings and PRODUCT > Storage.

Two hardening points sit outside the written spec: the meta CSP carries a directive browsers drop, and the shipped exe keeps Electron's default fuses, so `ELECTRON_RUN_AS_NODE` and `NODE_OPTIONS` are honored.

### Sender check split between `main.ts` and `handleCall`

Moving Bridge step 1 into `handleCall` is what makes the 403 cases unit-testable. `main.ts` now only reads the URL (confirmed):

```ts
// electron/main.ts
let sender: string | null = null
try { sender = e.senderFrame?.url ?? null } catch {} // disposed frame → reject
return handleCall(methods, rendererKey, sender, req)

// electron/ipc.ts, handleCall
try { key = senderUrl === null ? null : pageKey(senderUrl) } catch {}
if (key !== rendererKey) { log('warn', …); return { ok: false, status: 403, error: 'Not allowed' } }
```

ARCHITECTURE > Bridge still shows `pageKey(e.senderFrame.url)` and the 403 return inside the `ipcMain.handle` callback. Behavior is identical; the snippet should show the split so Phase 2 work does not re-add the check in main.

### Home refusal when the user installs into the app data folder

`allowToChangeInstallationDirectory: true` lets the user type any folder in the NSIS wizard. If it is `%LOCALAPPDATA%\TeleFlow`, the default home, `resolvePaths` sees `path.relative(appDir, home) === ''` and throws (the third `resolvePaths` test pins exactly this). `fatal` then shows "TeleFlow could not start" with "Set TELEFLOW_HOME to a folder outside …" on every launch (confirmed). The only fix an end user has is to reinstall elsewhere, and the message does not say so. The default `%LOCALAPPDATA%\Programs\TeleFlow` is unaffected, so this takes a deliberate choice to hit.

### CSP and the shipped binary

The renderer CSP is injected as a `<meta http-equiv>` tag. CSP3 ignores `frame-ancestors`, `report-uri`, and `sandbox` in meta-delivered policies, so `frame-ancestors 'none'` protects nothing and Chromium logs a console message about it on every load (confirmed).

The electron-builder config sets no `electronFuses`, so `TeleFlow.exe` keeps Electron's default fuses: `ELECTRON_RUN_AS_NODE=1` turns it into a plain Node runtime and `NODE_OPTIONS` is honored (confirmed). For an unsigned per-user binary the gain from flipping them is small (anyone who can set the environment can already run code as that user). `test:app` relies on the inspector and remote-debugging arguments Playwright passes, so `enableNodeCliInspectArguments` has to stay on unless the smoke test changes. Either outcome belongs in a Decision log row.

### Test coverage

`tests/engine.test.ts` covers the plan's `resolvePaths` and `pageKey` cases, adds a case-insensitive match and a same-prefix sibling folder, and exercises every `handleCall` branch (403, 404 incl. inherited names, 400, 429 passthrough, 500 without internals) plus the validators and `repoUrl`. Fixtures use made-up values (`9.9.9`, `example.test`), so the `app.info` test proves binding rather than typed-in values.

Not tested: the 32-hex mask in `log()`, the only guard if a later caller logs the API hash, and the 5 MB rotation in `openLog` (confirmed). Both fit in a few lines on a `mkdtemp` folder, and Ponytail asks security paths to leave a runnable check. The `tdlibVersion` error path and the `fatal` error box are also untested; they need a broken TDLib to exercise, so leaving them is reasonable.

### Leftovers and doc accuracy

`.gitignore` keeps FileGram's runtime state (`.td_database/`, `.td_files/`, `.management_uploads/`, `.filegram_state/`, `downloads/`, `.thumbs/`), its scratch and probe patterns (`runtime/`, `.scratch/`, `probe-*.js`, `tests/screenshot-*.png`, `tests/shot-*.png`, `tests/probe-*.png`), `config.json`/`settings.json`, and a comment about entries once written in UTF-16 (confirmed). TeleFlow writes none of these, and `downloads/` and `tmp/` hide a regression that writes data into the repo from a plain `git status` (only the Data gate's `--ignored` run would show it).

README says "The Electron binary downloads on first use (`npm run dev`, `npm run test:app`)", and the Early-risk "npm 12 install scripts" row lists Playwright `_electron` as a trigger. `tests/app.spec.ts` launches with `executablePath`, and Playwright only requires the `electron` package when no path is given, so `test:app` never downloads the binary (likely). Only `npm run dev` and the explicit `node -e "require('electron')"` do.
