## Shell structure and routing

The shell splits into three regions: a 40 px top bar (drag region with `env(titlebar-area-width)` reserved for the native window controls), a 170 px fixed sidebar, and a flex main area. Hash-based routing (`useRoute` watches `hashchange` and defaults to `/overview`) drives page selection. The six routes are Overview, Downloads, Uploads, Queue, Library (`/library`), and Settings. The auth gate (`auth.step !== 'ready'`) redirects to Login, which renders without the shell chrome.

The sidebar nav array defines six items with icons, labels, and an optional badge slot. Only Queue uses the badge, showing `activeCount` from `useLive()`. The badge hides at zero. No seventh Analytics item exists anywhere in the nav array or routing logic.

## Live data flow and the Queue badge

`useLive()` subscribes to app events through `useSyncExternalStore`. The store listens to the `window.teleflow.on` stream, filters for `auth` and `stats` events, and updates two values: `auth` (the full `AuthState`) and `activeCount` (the sum of queued + active + paused for both downloads and uploads). The Badge component returns `null` when `count === 0`, so the badge only appears when transfers are pending or in flight.

## Top bar: search and user menu

The search input sits left of the top bar (max 670 px wide) with a magnifying glass icon. Typing debounces at 250 ms via `setTimeout`, then calls `search.global({ q })` and displays results in an absolutely positioned popover. The popover has three sections: Chats (title + username), Downloaded files (name + chat), and Telegram link actions (Download media / Open chat). An empty result set shows "No matches". Clicking a chat navigates to `/downloads?chat=<id>`, clicking a file navigates to `/library?q=<encoded name>`, "Download media" calls `downloads.add({ link: query })` and toasts the result, "Open chat" calls `chats.open({ link, join: false })` and navigates to the returned chat.

The user menu button (right side of the top bar) shows an avatar with the user's first initial, name, and a chevron. Clicking toggles a popover menu with account details (name, phone, username if present), a Settings nav link, and a Log out button that calls `call('auth.logout', {})` after confirmation.

## Login flow coverage

`Login.tsx` implements six auth steps:

1. **credentials**: API ID (numeric input), API hash (text input), Continue button calls `auth.credentials({ apiId: Number(apiId), apiHash })`. A link to `my.telegram.org` appears below the button. Inline errors from rejections or `auth.error`.

2. **phone**: Phone input (`type="tel"`, `inputMode="tel"`), Send Code button calls `auth.phone({ phone })`. Back button calls `auth.logout({ local: true })` to reset to credentials. The error field includes `auth.error`, which surfaces TDLib auth states TeleFlow cannot complete (sign-up, email, Premium, other device).

3. **code**: Verification code input (`inputMode="numeric"`, `autocomplete="one-time-code"`), displays the phone from `auth.phone` and the delivery method from `auth.via` ("Telegram", "SMS", "phone call", or "another method"), Verify button calls `auth.code({ code })`.

4. **password**: Password input (`type="password"`), displays `auth.hint` when present, Continue button calls `auth.password({ password })`.

5. **starting** and **logging-out**: Centered loading text ("Starting…" / "Logging out…"), no controls.

All inputs are required, buttons show busy states, and errors display inline with `role="alert"`. The auth gate in `App.tsx` redirects to Login whenever `auth.step !== 'ready'`.

## AuthGuard and the step gate

The App component calls `useCall<AuthState>('auth.get', undefined, ['auth'])`, which subscribes to the `auth` event topic. When `auth.step !== 'ready'`, it renders `<Login />` without the shell chrome. Only when `auth.step === 'ready'` does it render the full shell with TopBar, Sidebar, and the routed page.
